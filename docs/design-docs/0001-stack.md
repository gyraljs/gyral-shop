# ADR 0001 — Stack

Status: **accepted** (2026-10-04)

- **TypeScript, strict, no Effect in app code.** Gyral 0.1 used Effect internally (0.2 dropped it); either way that is its
  business. App code uses plain TypeScript: tagged unions for results and errors, Promises
  for async. ESLint rejects `effect` imports.
- **Gyral** (core, http, router, time, ssr, testing), exact npm 0.3.1 (see the stable release addendum). Gyral
  has its own view layer since 0.3; the app imports `html`, `css`, `each`, `raw`, hooks and
  `prop` from `@gyral/core` and has no Lit dependency.
- **Hono** for routes and middleware, SSR via `@gyral/ssr`, served on Node by Gyral's adapter
  (`@gyral/ssr/node`'s `toNodeListener`; see the Node adapter addendum).
- **Drizzle ORM + SQLite** through `@libsql/client` (no native build step). Schema in
  `src/db/schema.ts`, SQL migrations generated by drizzle-kit into `drizzle/`, a deterministic
  faker seed for the catalog. Local file `data/shop.db`.
- **valibot** for every boundary. It implements Standard Schema, so the same schemas drive
  Gyral `form()` intents and server `formAction()`.
- **Testing:** Vitest browser mode (Chromium) for UI, Node project for domain/db/services and
  route tests against an in-memory SQLite, `axe-core` for accessibility (page tests and
  `pnpm ui:check`).
- **Local only** for now: no deployment target.

## Addendum: public origin (2026-10-04)

Absolute URLs (canonical links, sitemap, `robots.txt`, structured data, links in emails) use
`SITE_ORIGIN` (e.g. `https://shop.example`), validated as a bare http(s) origin and required
in production, because behind a proxy the request URL is internal. Without it (local
development) they fall back to the request's origin. Routes call `publicOrigin(c)`
(`src/server/origin.ts`). Same-origin checks (CSRF `Origin`, consent) still compare against
the request's origin.

## Addendum: production database settings (2026-10-04)

File databases open with `journal_mode = WAL` and `synchronous = NORMAL` (`openDb`).

- **Why WAL:** readers work from a snapshot and never wait for, or fail because of, a writer.
  Only writes need coordination, which the async write lock in `src/db/tx.ts` provides, and
  reads during a long checkout transaction keep flowing.
- **Why `synchronous = NORMAL`:** the recommended pairing with WAL. A committed transaction
  survives an application crash; on power loss the last transactions may roll back, but the
  database stays consistent. Acceptable here (a demo shop; payments are mocked).
- **No `busy_timeout`:** libsql's native driver is synchronous, so a busy wait blocks the event
  loop, including the open transaction it is waiting for, a self-deadlock until the timeout.
  Busy writes from other processes (e.g. `pnpm db:purge` beside the server) are retried
  asynchronously by `tx.ts` instead.
- **The write lock stays.** WAL still allows one writer at a time, and libsql runs each
  transaction on its own connection, so concurrent in-process writers would still collide.
  Removing the lock would need a driver with async busy handling or a single writer
  connection; revisit only with a measured need.
- WAL adds `shop.db-wal` / `shop.db-shm` beside the database (`data/` is gitignored); back up
  with SQLite's backup API or after a checkpoint, not by copying the main file alone.

## Addendum 2026-10-06: Gyral 0.2.0

Upgraded to `@gyral/*` ^0.2.0 (bead shop-1tc). Gyral no longer bundles Effect, so the main
entry's static graph dropped from 69.8 to 32.4 KiB gzip and all client JS from 124.0 to 85.3 kB.
`package.json` pins `lit-html` to 3.3.0 through `pnpm.overrides` until lit/lit#5298 (a
`repeat()` comment-node leak in 3.3.1+) is fixed upstream; remove the override then. (Removed
with Lit itself in Gyral 0.3, below.)

Gyral 0.2.0 also strips indentation whitespace from `html` templates, which changed every SSR
golden fixture (regenerated with `pnpm test -u`). One visible effect, a fix: the empty review
notice (`[data-component="review-notice"]:empty { display: none }`) was never empty before,
because the indentation around its binding counted as text, so it showed as a bar on every
product page. Tests that read `textContent` across sibling elements get no spaces between them
any more; read per element instead (see `test/browser/admin-manage.test.ts`).

## Addendum 2026-10-11: Gyral 0.3.1

0.3.1 was Gyral's one breaking step after 0.3.0; the shop migrated to it as it was developed
and runs on the npm release (see "Stable npm 0.3.1" below). What the shop took up:

- **Components:** the two-call `define<S, M, P>()(tag, spec)` everywhere, intent names from the
  parser keys; rows that name intents through a module constant use `intentsOf<typeof C>()`.
  `keyed()` replaces one-row `each()` remounts in the admin. The `define()`d tags get generated
  typings (`.gyral/elements.d.ts`, from `gyral-types` and the preset; `.gyral/` is ignored by
  ESLint and git). Components load automatically (addendum below).
- **Drivers:** provided once with `provideDrivers`, not per component: the storefront's CSRF
  http driver (`csrfHttp`, `src/ui/drivers/http.ts`) by the client entry, the admin's drivers
  by `<shop-admin>`'s module. `delay` and `debounce` come from `@gyral/time`.
- **Head model (Gyral ADR 0019):** the shell writes title, description, canonical, robots, Open
  Graph/Twitter meta and JSON-LD as Gyral's managed head; the favicon, theme stylesheet and
  CSRF meta stay in `extraHead`. Listing pages build their head with one pure function
  (`listingHead`), used by the category and search routes and by `<shop-listing>` after
  filtering or paging, so canonical, robots, description and breadcrumbs follow client
  updates. The admin shares `adminHead` the same way.
- **Forms:** each form definition lists its secret fields (passwords are secret by name), so
  rejected values never carry them, and Gyral never echoes a field named like `csrf`; the
  hand-written redaction is gone. `formAction` answers rejections as the JSON 422 itself; a
  middleware keeps `no-store` on the admin API.
- **Server:** `productionServer`'s `onResponse` adds the security headers to responses the app
  didn't make; `gyralDevServer` (`@gyral/ssr/node`) is the dev server; Gyral's Node adapter
  serves production (addendum below).
- **Errors:** every failure Gyral catches goes through one channel (`GyralError`, a bubbling
  `error` event, then `reportError`). It costs about 0.8 KiB gzip per page; the Gyral owner
  accepted that for 0.3.1. The shop defines no `error` view.
- `tsconfig.json` drops `useDefineForClassFields: false`, a leftover from Lit.

Not taken up: `clientOnly` (the shop server-renders); plain type guards for props (the props
use valibot schemas, which are Standard Schema); hook teardown (`defineHook({ dispose })`: no
hook needs it); style-attribute hashes (the server markup has no style attributes); the http
driver's `retry` wrapper and `timeoutMs`. The four admin `PropsChanged` reloads stay (one-shot
fetches, not long-lived work).

Size, against 0.3.0 (production build, gzip -9 of every script a cold load fetches): 0.3.1's
production trims (coded diagnostics, no prop path for property sets and seeds, unused
view-transition and frame code left out) took 0.7–1.0 KiB off every page; the error channel
added about 0.8 KiB, form secrets about 0.3 KiB, and the head model 1.1 KiB on category and
search (the price of correct canonical, robots and structured data after every filter or page
change). With the shop's hand-written loader, 0.3.1 pages weighed home 34,824, category
44,112 and product 44,049 B; automatic components took 0.4–0.5 KiB off each (addendum below).

## Addendum 2026-10-08: Gyral's Node adapter instead of `@hono/node-server`

`pnpm start`, `pnpm dev` and the HTTP test helper (`test/support/server.ts`) serve through
`createServer(toNodeListener(fetch, { origin }))` from `@gyral/ssr/node`; `@hono/node-server`
is no longer a dependency. Since Gyral 0.3.1, `toNodeListener` calls the handler as
`fetch(request, { incoming, remoteAddress })`, the env shape Hono's own adapter passes.

- **Client address.** Rate limiting keys on `ip(c)` (ADR 0002). `security/request.ts` reads
  the env's `remoteAddress` rather than `getConnInfo` from `@hono/node-server/conninfo` (which
  would work with the same env, but keeps the package); `hono/conninfo` only has types.
  In-process requests (`app.request` in tests) have no env and share the key `unknown`.
- **Through `productionServer`.** Its `fetch` passes the env on to the app
  (`productionServer<NodeEnv>`), so `createProdApp` hands it straight through. `prod.test.ts` › "rate-limits by the client
  address the Node adapter passes" fails if the address stops arriving.
- **Request URLs.** In production they are built on `SITE_ORIGIN` (the adapter's `origin`),
  no longer on the client's `Host` header, so a forged `Host` cannot change them, and over a
  TLS-terminating proxy with an `https:` `SITE_ORIGIN` the request counts as HTTPS. The dev
  server and tests keep the `Host` header.
- Static files are unchanged: `productionServer` (`assetHandler`, prerendered pages) serves
  them as before.

## Automatic components (2026-10-12)

The shop loads its components with Gyral 0.3.1's automatic components instead of its own loader:
`gyralVitePreset({ components: { modules } })` in `vite.config.ts` and `vitest.config.ts`,
`components` from `productionServer` / `gyralDevServer` passed to `renderPage`. The shop's
hand-written loader (a tag → module table in the client) and the per-page `chunks` lists that
preloaded its modules, with their tests, are gone. The entry keeps the shell components and the
page-wide http driver; browser tests load a page with `test/support/components.ts` and wait on
`componentsReady()`.

`vite.components.ts` overrides the scan twice: it lists the member forms (defined through
`defineMemberForm({ tag })`, which the scan can't see), and it maps the ten admin sections to
`src/ui/admin/app.ts`, which imports them all and provides their drivers. Without that, each
section becomes its own lazily loaded chunk and the build grows by about 12 KiB gzip.

The loader imports the entry, so the preload list `componentsFromManifest` gives it repeats the
entry's graph, and `renderPage` linked those modules a second time after the body.
`withoutHeadPreloads` (`src/server/prod-app.ts`) drops what the head already preloads;
`prod.test.ts` fails if a page links a module twice. (Bytes are unaffected: the browser fetches
each module once.)

Size, production build, cold load in Chromium after the loader is ready: every script and
stylesheet the page fetched, each compressed on its own (gzip -9, brotli q11), in bytes. All JS
chunks: every emitted `.js` file. Before is the hand-written loader on the same npm 0.3.1.
